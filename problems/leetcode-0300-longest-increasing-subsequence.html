找出最長的嚴格遞增子序列有多長

  • 給一個長度為 $n$ 的整數陣列 nums
  • 子序列：刪掉 0 個或多個元素，剩下的元素保持原本的順序，不必連續
  • 要嚴格遞增：$\text{nums}[i_1] \lt \text{nums}[i_2] \lt \cdots \lt \text{nums}[i_k]$，其中 $i_1 \lt i_2 \lt \cdots \lt i_k$
  • 輸入：整數陣列 nums
  • 輸出：最長的長度 $k$

限制

  • $1 \le n \le 2500$
  • $-10^4 \le \text{nums}[i] \le 10^4$
$n \le 2500$ 時，$O(n^2) \approx 6.25 \times 10^6$ 的 DP 就能通過；但題目的 Follow-up 要求 $O(n \log n)$。
「子序列」和「子字串」不一樣：子序列可以跳著選，只要順序不變。 「嚴格遞增」代表相等的數不能放在一起，所以 [7,7,7] 的答案是 1。

範例（Example 1）

INPUT

nums = [10,9,2,5,3,7,101,18]

OUTPUT

4

其他範例：nums = [0,1,0,3,2,3] → 4； nums = [7,7,7,7,7,7,7] → 1

選 Example 1 當主要範例，是因為它的數字忽大忽小，最能看出「換成更小的結尾」這個想法。

解題想法

暴力解

  • 枚舉所有 $2^n$ 個子序列，檢查是否遞增
  • 時間 $O(2^n \cdot n)$，$n = 2500$ 完全不可行

最佳解：貪心 + 二分搜尋

  • $\text{tails}[k]$：長度 $k+1$ 的遞增子序列，最小可能的結尾
  • 每個數用二分搜尋更新一格，時間 $O(n \log n)$
關鍵觀察：長度相同的遞增子序列，結尾越小越好，因為之後更容易接上新的數。$\text{tails}$ 一定嚴格遞增，所以可以二分搜尋： $$p = \min\{\, k \mid \text{tails}[k] \ge x \,\}$$ 找不到 $p$ 就把 $x$ 接在最後（長度 $+1$），找到就令 $\text{tails}[p] = x$。
介於兩者之間還有一種 O(n²) 的 DP：dp[i] 是以 nums[i] 結尾的最長長度，dp[i] = 1 + max{ dp[j] | j < i 且 nums[j] < nums[i] }。 這題 n ≤ 2500，O(n²) 也能通過，但 Follow-up 要求 O(n log n)。 貪心的想法是：我們不在乎子序列長什麼樣子，只在乎「每種長度目前最小的結尾」。結尾越小，後面越容易接上新的數。

程式碼（C++）

按 → 會依序高亮：第 4 行建立 tails；第 5–7 行對每個數，用 lower_bound 找第一個大於等於 x 的位置； 第 8–9 行找不到時接在最後，長度加 1；第 10–11 行找到時用 x 取代，讓結尾變小；第 14 行回傳 tails 的長度。 用 lower_bound（大於等於）而不是 upper_bound（大於），是因為題目要「嚴格」遞增，相等的數不能接在一起。

複雜度

項目複雜度原因
時間$O(n \log n)$每個數做一次二分搜尋，$\text{tails}$ 的長度最多是 $n$
空間$O(n)$$\text{tails}$ 最多存 $n$ 個數
$$T(n) = \underbrace{n}_{\text{elements}} \times \underbrace{O(\log n)}_{\text{binary search}} = O(n \log n)$$

對照：暴力解是 $O(2^n \cdot n)$；$O(n^2)$ 的 DP 在 $n \le 2500$ 時也能通過，但比較慢。
